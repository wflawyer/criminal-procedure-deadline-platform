# 开源与分享清单

## 当前已经完成

- 网页平台代码已纳入本地 Git 仓库。
- Codex Skill 已作为独立包放入 `codex-skill/calculate-criminal-deadlines`。
- Skill 包含确定性期限计算、输入校验、三类角色视角、程序目录、15 份本地法条文本和本地 JSON/Markdown 输出。
- 提供 `scripts/install_codex_skill.sh`；默认不覆盖用户已有的同名 Skill。
- 网页案件数据默认保存在浏览器 `localStorage`；Skill 案件数据默认保存在用户指定的本地文件。
- 当前工作区文件已经移除已发现的真实案件姓名，但现有 Git 历史中仍有 26 个提交包含该姓名，因此现有历史不符合直接公开条件。

## 发布前必须由仓库所有者决定

1. GitHub 仓库名称。建议使用 `criminal-procedure-deadline-platform`。
2. 仓库可见性。希望任何朋友直接访问和安装时选公开仓库；只给指定朋友使用时选私有仓库并邀请协作者。
3. 许可证。希望别人能够自由使用和修改时，可选择 MIT；如需更明确的专利授权条款，可选择 Apache-2.0。许可证应只覆盖有权许可的项目代码，内置法律文本仍应保留各自来源和覆盖范围说明。
4. 网页部署渠道和域名。GitHub 仓库链接只能下载源代码，不能替代网页访问地址。

## 必须采用干净发布历史

不要把当前本地仓库的完整 `main` 历史直接推送到公开 GitHub 仓库。推荐做法是：

1. 以通过隐私扫描的当前工作区文件建立一个全新目录。
2. 排除原 `.git`、构建产物、本地环境文件和案件数据。
3. 在新目录中重新执行 `git init`，把全部公开文件作为第一个提交。
4. 再次扫描真实姓名、联系方式、身份证件、访问令牌和本机绝对路径。
5. 只把这个全新历史推送到公开 GitHub 仓库。

如果必须保留原提交历史，需要先使用历史重写工具清除所有敏感内容并逐提交复核；这比创建干净快照风险更高，不作为默认方案。

## GitHub 发布后的朋友使用方式

### 使用网页

向朋友发送部署成功后生成的网站地址。朋友在自己的浏览器中录入案件，各浏览器的 `localStorage` 相互隔离。

### 使用 Skill

方法一：让朋友克隆仓库并执行：

```bash
bash scripts/install_codex_skill.sh
```

方法二：让朋友在 Codex 中使用 `$skill-installer`，安装公开仓库中的：

```text
codex-skill/calculate-criminal-deadlines
```

## 发布后仍应核对

- 从一个未登录、无本地数据的浏览器打开部署地址，确认看不到开发者案件数据。
- 用新的 Codex 环境安装 Skill，运行 `help`、`validate`、`calculate` 和 `verify-corpus`。
- 检查仓库历史、构建产物、环境变量和截图中是否包含真实姓名、联系方式、案件材料或访问密钥。
- 法律文本或节假日规则更新后，重新生成法条库、运行测试并更新 `checked_at`。
